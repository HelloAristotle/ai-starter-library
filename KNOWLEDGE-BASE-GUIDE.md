# Build a work knowledge base you can use

Hello Aristotle · [Back to the library](README.md)

## A small knowledge base that helps

Start with the facts you keep explaining. One checked page is enough to begin.

### What this is for

A knowledge base is simply a place to keep useful information. Your AI can use the relevant parts when you provide them. It might be a note, a document or a small folder. You do not need to build a complicated system before getting value.

### Your first finish

Make a short work note. Check that it is accurate. Save it somewhere you control. Use it in a fresh chat to draft one small thing, such as a reply or checklist. If that works, you have a useful starting point.

### Copy this to begin

```text
Help me make a small work knowledge base. Start by asking what I do and what
I keep having to explain. Ask one question at a time, and use what I already
tell you. After a few answers, draft a half-page work note with confirmed
facts, current priorities, useful preferences and open questions. Show me
the draft before saving anything. Keep private case details separate.
Explain what I should paste or attach in a fresh chat. Then help me try one
small task using the note. If you cannot save files, give me the complete
text to save myself. Don't claim the note is saved or will be remembered
without checking.
```

### You can stop here

You do not need to answer every possible question about your company. Add context when a real task reveals a useful gap. The rest of this guide helps you make that first note easier to reuse.

## Choose a place you already understand

Keep the setup simple enough that you can find and correct it yourself.

### If you use an ordinary AI chat

Keep your work note in a private document or notes app. Paste the relevant text, or attach the file when your chat supports it. In a new conversation, provide it again unless you have verified a feature that loads it. The tool's memory, project or folder features can differ; a pasted note is a useful starting route.

### If your AI can read a folder

Choose a permitted folder and tell the AI its location. Start with an index and a few small files. Ask it to identify which file it actually read before relying on the answer. A path written in a message does not itself grant access. Have it explain an unavailable file and use pasted text instead.

### A simple folder, when you need one

START-HERE.md: what is here and which note to use.
work.md: role, audience, confirmed services and preferences.
current-project.md: this project's goal, status and next step.
sources/: approved source material needed for the work.
archive/: superseded notes, clearly marked as old.

These are suggested names, not special commands. Plain documents work too. Add files only when separating the information helps.

### Keep these apart

Your personal preferences, shared company facts and individual customer records may need different locations and access. Start with information you are allowed to use in the chosen tool. Use a made-up example when permission is unclear.

## Write facts the next chat can use

A clear note beats a pile of unexplained documents.

### Copyable blank work note

```text
ABOUT MY WORK
What I do:
Who I help:
Confirmed services or responsibilities:

CURRENT FOCUS
Priority now:
What is still undecided:

HOW TO HELP
Audience and writing preferences I confirmed:
What to ask me each time:

SOURCES
Where the important facts came from:
Last checked by me:
What may go out of date:
```

### Fictional filled example

Meadow Lane helps homeowners with low-water gardens. Our current focus is clearer replies to enquiries. Use warm, short emails. Ask each time for the customer's actual request and any agreed next step. Do not assume a standard price or available starting date. Source: owner-provided work note. Last checked: add the actual date when reviewed. Pricing and availability remain open.

### Useful context versus extra context

For a customer reply, the customer's question, approved service description and current commitments matter. An old business plan or an entire inbox probably does not. Save lasting facts once, then supply fresh case details with each task. Do not store a temporary deadline as a permanent company rule.

## Bring in sources with a purpose

Choose the material that changes the result you want.

### Start with one output

Name the thing you want: a reply, checklist, meeting recap or short comparison. Ask the AI which missing information would improve that output most. Share a small, relevant excerpt first. Keep the original document or source link so you can check the summary.

### Copy this before adding more files

```text
I want to make one specific output. Help me choose the smallest useful
context for it. First ask what I want to produce and who will use it. Then
ask what materials I have, without requesting the whole archive. Recommend
at most three inputs and explain why each matters. Start with the most
important one. Use only material I am allowed to share. If something is
missing, narrow the task or mark the gap. Once you have enough information,
make a first version.
```

### Give each source a small label

Name: Workshop outline
Use for: what the session covers
Owner: person responsible for keeping it current
Last checked: actual review date
Status: approved, draft or historical
Location: a path or link you can open

The label helps both you and the AI avoid using an old draft as a current promise.

### When sources disagree

Do not blend conflicting prices, dates or policies into one confident answer. Identify the conflict, find the current authority and resolve it with the responsible person. Until then, keep the affected statement open.

## Check reuse, then keep it current

A note is useful when it improves a fresh task and stays easy to correct.

### Try this in a fresh chat

```text
Use the work note I have pasted or attached for this new task. First name
the source you actually read and give two relevant facts from it. Tell me if
a needed source is missing. Then help me make a short customer reply using
only the fresh case facts I supply. Ask about missing commitments rather
than guessing. After the draft, point out which saved context helped and
which facts still need my check.
```

### A small test you can judge

Practice only: Meadow Lane has been asked when a garden project can start. The saved note says availability is not set. A useful draft asks for or leaves open the starting date. A draft promising next Tuesday fails the test. Read the note and output yourself; the AI saying it used the context is not enough.

### When something changes

```text
Compare my current work note with this confirmed update. Show what stays,
what changes and any conflict that needs my answer. Do not assume a newer
draft overrides an approved source. Give me a revised note and a short
change note. Keep unresolved facts labeled. Show the exact contents and
location before any save; if saving is available and I ask for it, read the
file back to confirm.
```

### Make one current copy obvious

Update the note when a fact changes. Add the actual review date and keep important source links. Mark old copies as historical so they are not used by accident. Re-run one small task if the change affects what the AI should say or do.

## Grow it when the work asks for more

Use a real task to decide what belongs in the next version.

### Optional questions for later

Which questions do customers ask repeatedly? Which terms do we use differently from other companies? What does a good finished example look like? Which claims require an approved source? Which information changes often? Who is responsible for correcting it? Answer one when it becomes relevant.

### When a team starts using it

Choose an owner for shared facts. Make approved and draft material easy to distinguish. Decide which tools and locations the team may use. Keep private customer cases separate from reusable methods. Try one shared task with a second person and watch where they need help before expanding the system.

### Your context and your methods

Context says what is true about the work. A method says how to perform a task. Keep them separate so a changed fact does not require rewriting every prompt. Example: work.md describes the business; a reply method asks for the reader, purpose, approved facts and next step. Together they help make a useful draft.

### A simple finish check

Can you find the current note? Can you explain where its important facts came from? Can you correct it? Can a fresh chat use the relevant parts on a new example without inventing missing facts? If yes, you have a practical foundation. Keep improving it through the work you already need to do.
