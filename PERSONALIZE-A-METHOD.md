# Make a method useful for your work

Start with a result you have checked and would use. Then save the few instructions that helped produce it.

## 1. Name what worked

You might say, "The reply answered the question immediately," "The action list left missing dates open," or "The comparison used the same criteria for every option."

## 2. Ask for a reusable method

```text
Turn the way we made this checked result into a short reusable method. First
identify which parts are repeatable and which were facts for this one case.
Keep changing company facts, names, prices, and dates out of the method.
Refer to my current context note for those.

Include when to use the method, the input it needs, a few clear steps, what
a finished result looks like, and how I should check it. Preserve the
corrections I actually asked for, without turning a one-time choice into a
permanent rule. Show me the method before saving. Ask only if a missing
answer would change it.
```

## 3. Keep it somewhere simple

A private note called "My customer reply method" is enough. If you have a workspace folder, a methods folder can hold it. Give the AI the method when you use it; do not assume a filename makes it load automatically.

If your method says "Always promise delivery in three days," ask whether that was actually a standing policy or just one case. Put current delivery terms in their authoritative context source and have the method check them.

## 4. Try a different example

Start a fresh chat, provide the method and relevant context, then a new input. Check whether it handles missing information without making it up. If it fails, change the smallest instruction that caused the problem.

## Later: native skills

Some tools support saved skills that they can discover automatically. That is optional. First prove the method helps when read explicitly. If you later want native installation, use the current official documentation for your exact tool, preserve existing instructions, and test that the correct method loads in a fresh chat.
