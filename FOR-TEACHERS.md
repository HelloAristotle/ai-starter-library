# Guide someone through their first useful result

Choose a real task they care about and a small finish they can judge. If they want a context note first, let that note be the finish.

## A simple session

1. Ask what they keep repeating or wish they could finish. Use the app they already have access to.
2. Paste the [setup prompt](SETUP-PROMPT.txt) together. Let the learner answer in their own words.
3. Choose one example with appropriate information. Use the [fictional meeting](EXAMPLES.md) if real material is unsuitable.
4. Have them read the result and name one thing that is right and one thing to change.
5. Make that correction. Save a short note or method only if it helps future work.
6. Ask them to start a fresh chat and try a new example with the saved material.

## What to notice

Can the learner explain what the AI used? Can they find the saved note themselves? Do they catch an invented promise or missing deadline? Can they ask for a correction in ordinary words? These observations tell you more than whether the AI produced a long answer.

If setup gets in the way, use pasted text and finish the exercise. Keep app installation and deeper infrastructure as separate steps. Do not infer permission to retain or publish a learner's inputs, story, or outcome.

## Optional next questions

Ask only when useful: What do you explain repeatedly? Which source is current? What changes often? Who should be able to see it? What would a good example look like? Which second task would use the same context?

When a team wants a shared system, discuss source ownership, access, updates, and one pilot workflow. A successful practice draft is a starting point, not proof of adoption or a promised business result.
